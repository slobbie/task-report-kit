# 보고서 한국어 작성 기준

`task-asis`, `task-asis-tobe`, `task-tobe`가 만드는 보고서와 채팅 보고에 적용한다. 사용자의 현재 요청과 사실 보존을 우선한다. 일반적인 한국어 작성 판단은 `natural-writing-kr` 스킬이 설치되어 있으면 그 기준을 함께 따른다.

## 문장

- 문체는 합니다체로 통일한다. 항목 설명, 캡처 설명, 번호 설명, 정리 상자 모두 같다.
- 단어를 묶으려고 가운뎃점을 넣지 않는다. 쉼표나 슬래시로 일괄 교체하지도 않는다. 문장은 조사와 서술어로 관계를 설명하고, 의미 구분에 필요한 쉼표만 쓴다. 코드, 정확한 인용문, 고유명사, 원문 데이터는 그대로 둔다.
  - 나쁜 예: 개발 환경 · 가상 데이터
  - 좋은 예: 개발 환경에서 가상 데이터로 확인했습니다.
- 근거 없는 효과와 수식어를 쓰지 않는다. 혁신적, 획기적, 완벽한, 극대화 같은 표현은 지우거나 확인된 행동과 수치로 설명한다. 작업 분담을 확인하지 않고 '승인만 하면 된다'고 단정하지 않는다.
- 자연스럽게 보이려고 의미를 흐리지 않는다. 인증, 권한, API, 트랜잭션 같은 정확한 개념은 유지하고 독자에게 필요한 설명만 덧붙인다. 모든 한자어를 순우리말로 바꾸거나 모든 명사형을 문장으로 늘리지 않는다.
- 제목, 표 머리, 단계명은 짧은 명사구로 써도 된다. 설명 본문은 주체, 행동, 대상이 드러나는 문장으로 쓴다. 제목 아래에서 같은 뜻을 부제와 결론으로 반복하지 않는다.
- 원문의 숫자, 단위, 조건, 부정, 예외, 책임 주체를 보존한다. 확인된 사실과 추정을 구분한다. 출처 없는 수치와 인과관계를 만들지 않는다.

## 화면 변경 보고서

- 기능명과 화면 요소는 현업 용어로 쓴다. 이미지 변경, 문구 수정, 미리보기, 비활성화 같은 표현을 무조건 쉬운 말로 풀지 않는다. 실제 화면의 버튼과 라벨을 인용할 때는 원문을 유지한다.
- 동작을 장황한 명사구로 만들지 않는다. 한 번 누르면 편집이 끝나는지, 수정 창만 열리는지 구분해서 쓴다.
- 주어와 서술어가 같은 행동을 반복하거나 서로 맞지 않는지 확인한다.
- '그 장', '글', '자리' 같은 표현이 가리키는 대상이 무엇인지 확인한다. 대상을 알 수 없으면 내용을 추정해서 채우지 않는다.

## 보고서에 넣지 않는 것

- 제작 과정 설명("개발 환경에서 화면을 열었다", "시안과 공식 문서를 조사했다")과 포괄적인 면책 문구를 표지, 부제, 각주, 마지막 장에 넣지 않는다. 출처 인용은 해당 사실을 뒷받침하는 위치에만 둔다.
- 요청하지 않은 '확인 필요', '미결 사항', '확인하지 못한 사항' 절을 만들지 않는다. 확인하지 못한 것은 채팅 보고에 구체적으로 쓴다.
- 실제 동작의 필수 조건은 해당 기능 설명에 직접 쓴다. '확인이 필요합니다' 같은 일반 안내로 대신하지 않는다.
- 예시 숫자를 실측값처럼 쓰지 않는다. 예시 숫자가 있는 표나 화면에만 '예시'를 짧게 표시한다.
- 사용자가 지운 절과 문구는 다시 만들지 않는다.

## 검사 도구

`scripts/audit_report.py <보고서.html>`은 화면에 보이는 글에서 가운뎃점과 검토할 표현을 찾는다. 결과가 깨끗해도 자연스러운 한국어이거나 사실이 정확하다는 뜻은 아니므로, 문장은 직접 다시 읽는다.

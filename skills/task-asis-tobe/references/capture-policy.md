# 화면 캡처 순서와 운영 환경 사용 기준

`task-asis`, `task-asis-tobe`, `task-tobe`가 함께 따른다.

## 결과물은 항상 HTML 보고서다

캡처를 하나도 못 해도 HTML 보고서는 만든다. md 파일이나 채팅 답변으로 보고서를 대신하지 않는다.

## 캡처 순서

화면을 찍을 방법을 아래 순서로 찾는다. 앞 단계가 막혔다고 바로 건너뛰지 말고, 막힌 이유를 확인하고 풀 수 있으면 푼다.

1. **개발 환경**: 개발 서버나 개발 빌드를 직접 띄워서 찍는다(실행 명령은 `package.json`, README, 프로젝트 규칙에서 찾는다). 서버 연결이 안 되면 서버를 띄웠는지, 포트와 주소가 맞는지, 의존성 설치가 필요한지 먼저 본다. 웹은 Playwright(`scripts/web_capture.mjs`)로 찍는다. 다른 브라우저 도구가 없다는 이유로 멈추지 않는다.
2. **테스트 데이터**: 로그인이나 특정 데이터가 필요하면 사용자에게 테스트 계정을 한 번 묻는다. 없으면 개발 환경에서만 응답을 바꿔 화면을 넘긴다(웹은 `page.route()`, 앱은 `TEMP-CAPTURE` 임시 코드).
3. **운영 환경**: 개발 환경을 쓸 수 없으면 아래 "운영 환경 사용 기준"을 지키며 운영 화면을 찍는다.
4. **캡처 실패**: 그래도 못 찍으면 그 항목의 AS-IS 칸에 "캡처하지 못함: <이유>"를 적고, 코드로 확인한 현재 동작을 글로 쓴다. 이유에는 시도한 방법과 막힌 지점을 쓴다(예: "로컬 서버 실행 실패 — 환경변수 SUPABASE_URL 없음"). 보고 메시지에도 캡처하지 못한 항목과 이유를 적는다.

글만 있는 AS-IS는 4번까지 시도하고 실패한 경우에만 쓴다. 캡처를 건너뛰는 이유로 쓰지 않는다.

## 운영 환경 사용 기준

1. **처음 한 번은 묻기**: 그 프로젝트에서 운영에 처음 접속하기 전에 사용자에게 확인받는다. 이때 운영 주소와 사용할 계정을 받는다. 같은 프로젝트의 이후 작업에서는 다시 묻지 않는다. 사용자가 확인한 내용(프로젝트, 주소, 계정 종류, 날짜)은 메모리나 작업 기록처럼 다음 작업에서 볼 수 있는 곳에 남긴다.
2. **보기만 하기**: 화면을 열고 이동하는 것까지만 한다. 저장, 신청, 결제, 문자 발송, 삭제, 설정 변경처럼 데이터가 바뀌거나 밖으로 나가는 동작은 실행하지 않는다. 그 단계는 직전 화면까지만 찍고 "운영이라 실행하지 않음"으로 적는다.
3. **응답을 바꾸지 않기**: `page.route()` 응답 바꾸기나 `TEMP-CAPTURE` 같은 임시 처리는 운영에 쓰지 않는다. 운영 화면은 실제로 보이는 그대로만 찍는다.
4. **개인정보 가리기**: 캡처에 다른 사람의 이름, 연락처, 프로필, 주소 같은 실제 정보가 보이면 보고서에 넣기 전에 가린다. 웹은 찍기 전에 해당 요소를 흐리게 처리하고(`page.addStyleTag`로 `filter: blur()`), 앱은 찍은 뒤 이미지에서 가린다. 가렸다는 사실을 캡처 설명에 적는다.
5. **출처 표시**: 운영에서 찍은 캡처는 설명에 "운영 화면"이라고 적는다.

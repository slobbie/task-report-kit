# Task Report Kit

[English](README.md)

작업 전에는 바꿀 점을 검토하고, 작업 뒤에는 실제 화면으로 검증해 번호 달린 AS-IS/TO-BE HTML 보고서로 정리하는 Codex와 Claude Code용 스킬입니다. 모바일 앱(iOS, Android)과 웹 서비스에서 쓸 수 있습니다.

<img width="2400" height="1084" alt="AS-IS/TO-BE report example" src="https://github.com/user-attachments/assets/458d3509-1976-4432-98dd-fb38c6bf7acf" />

위 이미지는 [examples/coupon-checkout](examples/coupon-checkout) 예시 보고서의 첫 항목입니다. 사용 기한이 지난 쿠폰이 결제에 그대로 적용되던 가상 쇼핑몰을 고친 사례입니다. 예시 앱의 수정 전후 화면을 `web_capture.mjs`로 찍고, `build_report.py`로 보고서를 만들었습니다. `report.html`을 내려받아 브라우저로 열면 플랫폼 전환 토글을 직접 눌러 볼 수 있습니다.

## 들어 있는 스킬

| 스킬 | 언제 쓰나요 | 결과물 |
| --- | --- | --- |
| `task-plan` | 기획서, 정책서, 피그마, 개선 요구를 받고 작업을 시작하기 전 | 현재 화면 캡처에 문제를 번호로 표시한 AS-IS와, 같은 번호로 무엇을 왜 바꿀지 적은 TO-BE, 태스크 목록이 담긴 검토 보고서 |
| `task-asis-tobe` | 태스크 하나를 구현하거나, 이미 구현된 작업을 검증할 때 | 수정 전후 실제 화면을 나란히 놓고 바뀐 점과 해결된 문제를 번호로 짝지은 결과 보고서 |

두 스킬은 보고서 생성기와 작성 기준을 함께 쓰므로 같이 설치해야 합니다.

## 어떤 일을 하나요?

- 시안이나 추측한 화면이 아니라 실제로 실행한 화면을 캡처합니다. 개발 환경, 테스트 데이터, 운영 환경(보기만 하고 개인정보는 가림) 순서로 시도합니다.
- 화면에서 바뀌는 곳에 번호를 달고, 같은 번호로 AS-IS의 문제와 TO-BE의 개선을 짝지어 씁니다. 번호 위치는 손짐작이 아니라 요소 좌표나 픽셀 측정으로 잡습니다.
- AS-IS에는 누가 무엇 때문에 어떤 결과를 겪는지 쓰고, TO-BE에는 바뀐 뒤 상태와 그래서 사라지는 문제를 씁니다.
- iOS와 Android처럼 같은 화면을 다루는 플랫폼은 토글 하나로 바꿔 봅니다.
- 캡처를 위해 넣은 임시 코드는 `TEMP-CAPTURE` 표시를 달고 끝나면 지운 뒤 확인합니다. 문자 발송이나 결제처럼 실제로 나가는 동작은 실행하지 않습니다.
- 보고서 문장은 아래 작성 기준을 따릅니다.

## 보고서 작성 기준

보고서는 읽는 사람이 무슨 일이 왜 생겼는지 한 번에 이해하도록 씁니다. 전체 기준은 [item-writing.md](skills/task-asis-tobe/references/item-writing.md)(항목 쓰는 법)와 [korean-writing.md](skills/task-asis-tobe/references/korean-writing.md)(한국어 문장)에 있습니다.

**AS-IS와 TO-BE**
- AS-IS에는 기능 설명이 아니라 문제를 씁니다. 누가, 무엇 때문에, 어떤 결과를 겪는지가 들어가야 합니다.
- TO-BE에는 할 일만 쓰지 않고, 바뀐 뒤 상태와 그래서 AS-IS 몇 번 문제가 어떻게 사라지는지 씁니다.
- 번호 하나에 설명 하나만 씁니다. 캡처 번호의 설명이 곧 그 번호의 문제 문장입니다.

| 나쁜 예 | 좋은 예 |
| --- | --- |
| AS-IS ① 쿠폰 확인 함수가 결제 단계에서 만료일을 다시 확인하지 않습니다. | AS-IS ① 회원이 장바구니에서 쿠폰을 적용한 뒤 사용 기한이 지나서 결제해도, 만료된 쿠폰 할인이 결제 금액에 그대로 남습니다. 운영자는 기한이 끝난 쿠폰만큼 할인된 주문을 받게 됩니다. |
| TO-BE ① 만료 쿠폰 처리 기준을 정해 반영합니다. | TO-BE ① [결제하기]를 누르는 시점에 서버가 쿠폰 사용 기한을 다시 확인하고, 기한이 지났으면 할인 전 금액을 보여 줍니다. 만료된 쿠폰으로 결제되지 않으므로 ①의 할인 주문이 사라집니다. |

**읽는 사람이 한 번에 이해하게**
- 확인하는 대상을 구체적으로 씁니다. "검증"이 아니라 "쿠폰 사용 기한 확인"처럼 쓰고, 왜 실패하는지도 같은 문장에 씁니다.
- 결과는 화면에 보이는 것, 저장할 때 생기는 문제, 다시 열었을 때 보이는 것 순서로 씁니다.
- 직접 확인한 문제와 테스트하지 않은 동작을 섞지 않습니다. 실행해 보지 못한 동작을 "~할 수 있습니다"로 문제처럼 쓰지 않고, 테스트가 더 필요하다는 이유로 개선안을 만들지 않습니다.
- 이미 되는 동작을 먼저 확인하고, 요구와 무엇이 다른지를 씁니다.

**보고서에 넣지 않는 것**
- "개발 환경에서 화면을 열었다" 같은 작업 과정과 포괄적인 면책 문구
- 요청하지 않은 '확인하지 못한 사항', '미결 사항' 절. 확인하지 못한 것은 채팅 보고에 씁니다.
- 사용자가 지운 내용. 문장을 다듬으면서 되살리지 않습니다.

**문장**
- 합니다체로 통일합니다.
- 단어를 가운뎃점으로 잇지 않습니다. "개발 환경 · 가상 데이터" 대신 "개발 환경에서 가상 데이터로 확인했습니다"처럼 조사와 서술어로 관계를 씁니다.
- 혁신적, 획기적, 완벽한, 극대화처럼 근거 없는 수식어는 쓰지 않고 확인된 행동과 수치로 설명합니다.
- 숫자, 조건, 예외, 책임 주체는 원문 그대로 지키고, 확인된 사실과 추정을 구분합니다.

## 설치하기

### skills CLI

```bash
npx skills add slobbie/task-report-kit
```

설치 과정에서 두 스킬을 모두 고르고, Codex, Claude Code 또는 둘 다 고르세요. 사용자 전체에 설치하려면 `-g`를 붙입니다.

### 설치 스크립트 (macOS, Linux)

```bash
git clone https://github.com/slobbie/task-report-kit.git
cd task-report-kit
./install.sh          # Codex(~/.agents/skills)와 Claude Code(~/.claude/skills)에 복사
./install.sh --link   # 복사 대신 링크. git pull로 업데이트할 때 편합니다
```

이미 설치된 폴더는 덮어쓰지 않습니다. 업데이트할 때는 기존 폴더를 확인하고 지운 뒤 다시 실행하세요.

### 함께 쓰면 좋은 스킬

한국어 문장 판단은 [natural-writing-kr](https://github.com/slobbie/natural-writing-kr)를 같은 skills 폴더에 설치하면 함께 적용됩니다. 설치하지 않아도 보고서 전용 작성 기준은 적용됩니다.

## 필요한 도구

- 공통: Python 3, Google Chrome (보고서 렌더링 확인)
- 웹: Node.js, Playwright (작업용 임시 폴더에 설치하며 프로젝트 의존성은 건드리지 않습니다)
- 모바일 앱: Xcode 시뮬레이터, Android 에뮬레이터와 `adb`, [Maestro](https://maestro.mobile.dev)

모바일 절차는 React Native(Expo 개발 빌드)에서 검증했습니다. 다른 스택도 순서는 같고 빌드 명령만 프로젝트에 맞추면 됩니다.

## 사용하기

Claude Code는 `/task-plan`, `/task-asis-tobe`, Codex는 `$task-plan`, `$task-asis-tobe`로 부릅니다.

```text
/task-plan 첨부한 기획서와 피그마 링크를 보고 회원가입 화면 개편 작업 전에 바꿀 점을 검토해 줘
```

```text
/task-asis-tobe 로그인 화면에 비밀번호 찾기 링크를 추가하고 iOS, Android 전후 화면으로 보고해 줘
```

보고서는 HTML 파일 하나로 나오며 이미지가 파일 안에 들어 있어 그대로 공유할 수 있습니다. 확인하지 못한 것과 작업 과정은 보고서가 아니라 채팅 보고에 적습니다.

## 보조 도구

- `skills/task-asis-tobe/scripts/build_report.py`: manifest(JSON)로 보고서 HTML을 만듭니다. 형식은 파일 첫머리 주석에 있습니다.
- `skills/task-asis-tobe/scripts/web_capture.mjs`: Playwright로 단계별 화면을 찍고 번호 위치를 요소 좌표로 저장합니다.
- `skills/task-asis-tobe/scripts/audit_report.py`: 보고서에서 가운뎃점과 검토할 표현을 찾습니다. 걸린 곳이 없어도 자연스러운 문장이라는 보장은 아닙니다.
